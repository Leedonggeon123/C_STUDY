IN THIS CHAPTER

SECTION 01

프로그램과 C 언어

프로그램은 결국 "할 일의 순서"다. 라면을 끓일 때도 물 붓기 → 끓이기 → 면 넣기 → 스프 넣기 순서가 있는 것처럼, 컴퓨터에게도 순서대로 일을 시켜야 한다. 그런데 "스프 적당히 넣기" 같은 말은 사람은 알아듣지만 컴퓨터는 못 알아듣는다. 그래서 오해 없이 쓰는 규칙을 정해놨고, 그게 프로그래밍 언어다. C는 그중 하나.

C 언어는 왜 만들어졌나

  • 1972년에 데니스 리치가 만들었다. 켄 톰슨의 B 언어를 발전시킨 것.
  • 당시 유닉스(운영체제)는 어셈블리어로 짜여 있어서 컴퓨터 기종이 바뀌면 처음부터 다시 만들어야 했다. 기종에 상관없이 쓰려고 만든 게 C.
  • 그 뒤로 표준이 계속 정해졌다. 1989년 ANSI C, 1999년 C99, 2011년 표준. 이 책은 C99 기준.

장점은 크게 세 가지로 기억하면 된다.

장점 한마디로
시스템 프로그래밍 운영체제를 만들려고 만든 언어라 하드웨어를 직접 다룰 수 있다
이식성 표준만 지키면 다른 컴퓨터에서도 같은 코드가 돌아간다
함수 단위 개발 기능별로 나눠 짜서 고치기 쉽고 다른 프로그램에 재활용도 된다

표준에 없는 문법을 쓰면 특정 컴파일러에서만 돌아가서 이식성이 깨진다는 점도 알아두자.

SECTION 02

컴파일이 뭔가

사람이 쓴 코드(소스 파일)는 컴퓨터가 바로 못 읽는다. 컴퓨터는 0과 1로 된 기계어만 이해해서, 중간에 번역하는 과정이 필요하다. 그게 컴파일이고, 번역하는 프로그램이 컴파일러다.

OUTPUT
소스 파일(.c) → 컴파일 → 실행 파일(.exe) → 실행

코드를 고치면 다시 컴파일해야 바뀐 게 반영된다. 처음엔 이걸 깜빡하고 "왜 안 바뀌지?" 하게 된다.

안쪽을 더 들여다보면 3단계

비주얼 스튜디오에서는 버튼 한 번(Ctrl+Shift+B)이지만 속에서는 세 단계가 돌아간다.

  1. 전처리: #include 같은 지시자대로 소스를 가공한다. 필요한 파일을 불러와 붙이고, 주석도 이 단계에서 지워진다.
  2. 컴파일: 전처리된 소스를 기계어로 바꿔서 개체 파일(object file)을 만든다. CPU가 읽는 명령어로는 되어 있지만 이것만으로는 실행이 안 된다. 프로그램은 운영체제가 실행해주는 것이라, 운영체제가 알아보는 형태로 한 번 더 손봐야 하기 때문.
  3. 링크: 개체 파일에 startup code를 붙여서 실행 파일을 완성한다. startup code는 실행 전 준비 작업을 하고 main 함수를 불러주는 코드다. 그래서 C 프로그램에는 항상 main이 있어야 한다.
OUTPUT
소스 파일 → (전처리) → 전처리된 소스 → (컴파일) → 개체 파일 → (링크, startup code 추가) → 실행 파일
SECTION 03

비주얼 스튜디오로 첫 프로그램 만들기

이 책은 Visual Studio 2019 Community(줄여서 VC++)로 실습한다. 순서만 정리해둔다.

설치할 때

  • 설치 도구에서 "C++를 사용한 데스크톱 개발" 항목을 체크해야 C 컴파일러가 깔린다.
  • 로그인 없이 쓰면 30일 평가판이고, 마이크로소프트 계정으로 로그인하면 계속 무료다.

프로젝트 만들기

  1. [새 프로젝트 만들기] → [빈 프로젝트] 선택
  2. 프로젝트 이름 입력(예: first), 위치는 찾기 쉬운 폴더로 지정
  3. [솔루션 및 프로젝트를 같은 디렉터리에 배치]에 체크: 안 하면 폴더가 한 겹 더 생겨서 구조가 복잡해진다.

프로젝트는 프로그램을 만드는 작업 공간이자 관련 파일을 묶어두는 폴더라서, 새 프로그램을 만들 때마다 프로젝트부터 만든다.

소스 파일 추가

  • [솔루션 탐색기]에서 [소스 파일] 우클릭 → [추가] → [새 항목] → [C++ 파일] 선택
  • 이름은 main.c처럼 확장자를 반드시 .c로 쓴다. 확장자를 안 쓰면 자동으로 .cpp가 붙는데, 그러면 C++ 규칙으로 컴파일돼서 결과가 달라질 수 있다.

컴파일 → 실행

할 일 단축키 메뉴
컴파일(빌드) Ctrl + Shift + B [빌드] → [솔루션 빌드]
실행 Ctrl + F5 [디버그] → [디버그하지 않고 시작]

컴파일하면 프로젝트 폴더 안에 Debug 폴더가 생기고 거기에 프로젝트이름.exe가 들어간다.

exe를 직접 더블클릭하면 창이 바로 닫힌다

결과가 찍히자마자 콘솔 창이 닫혀서 아무것도 못 본다. 코드 끝에 창을 붙잡아두는 한 줄을 넣으면 된다.

C
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("Be happy!\n");
    system("pause");    // 아무 키나 누를 때까지 창을 유지
    return 0;
}

system은 운영체제 명령을 실행하는 함수고, 명령은 운영체제마다 다르다. Windows 콘솔 창을 붙잡아두려고 쓰는 정도로만 알아두면 된다. Ctrl+F5로 실행하면 이미 창이 유지돼서 필요 없다.

컴파일 오류가 났을 때

일부러 문장 끝의 ;를 지우고 컴파일해보면 오류 메시지가 뜬다. 메시지를 더블클릭하면 해당 줄로 이동하는데, 이동한 줄이 실제로 틀린 줄이 아닐 때가 있다. ;가 빠지면 컴파일러는 다음 줄까지 한 문장으로 이어서 읽기 때문에 "다음 줄이 이상하다"고 말한다. 그래서 표시된 줄이 이상해 보이지 않으면 바로 위 줄 끝을 확인하자. 오류를 고치는 작업을 디버깅이라고 한다.

프로젝트 템플릿 만들어두기 (선택)

VS는 보안 검사를 엄격하게 해서 scanf 같은 함수에 경고를 에러처럼 띄운다. 매번 막히지 않으려면 처음에 한 번만 설정해서 템플릿으로 저장해두면 편하다.

  1. 빈 프로젝트를 만들고 HonGong.c 같은 소스 파일을 추가
  2. 소스 파일 우클릭 → [속성] → [구성 속성] → [C/C++] → [전처리기] → [전처리기 정의]에 _CRT_SECURE_NO_WARNINGS 추가
  3. [프로젝트] → [템플릿 내보내기] → [프로젝트 템플릿]으로 저장

다음부터는 [빈 프로젝트] 대신 이 템플릿을 고르면 된다. 코드 맨 위에 #define _CRT_SECURE_NO_WARNINGS를 직접 쓰는 방법도 있다.

SECTION 04

제일 기본 뼈대

C
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
  • #include <stdio.h>: 입출력 함수(printf, scanf 등)를 쓰려고 불러오는 것. 전처리 단계에서 처리된다.
  • int main(void): 프로그램이 시작되는 곳. C 프로그램은 항상 main부터 실행된다.
  • { }: main이 실행할 내용을 묶는 중괄호.
  • printf(...): 화면에 출력.
  • ;: 명령 하나가 끝났다는 표시.
  • return 0;: 문제없이 끝났다고 운영체제에 알려주는 값.
SECTION 05

오류 종류

종류 언제 나오나 예
문법 오류 컴파일할 때 세미콜론 빠짐, 괄호 짝 안 맞음
논리 오류 실행은 되는데 결과가 이상함 계산식을 잘못 짬

문법 오류는 컴파일러가 줄 번호까지 알려줘서 찾기 쉽다. 진짜 힘든 건 논리 오류다. 에러는 안 나는데 답이 틀리니까 직접 값을 찍어보면서 따라가야 한다.

오류 메시지는 첫 번째 것부터 본다. 앞에서 하나 틀리면 뒤에 줄줄이 따라 나오는 일이 많아서, 첫 번째만 고치면 나머지가 같이 사라지기도 한다.
