SECTION 01

프로그램이 만들어지는 과정

C로 짠 코드는 그대로 실행되지 않는다. 사람이 읽는 코드(소스 파일, .c)를 컴파일러가 기계어로 바꿔줘야 실행 파일이 나온다.

OUTPUT
소스 코드(.c) → 컴파일 → 실행 파일(.exe) → 실행

코드를 고치면 반드시 다시 컴파일해야 바뀐 내용이 반영된다. 처음엔 이걸 깜빡하고 "왜 안 바뀌지?" 하게 되는 일이 많다.

SECTION 02

제일 기본 뼈대

C
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}

한 줄씩 뜯어보면 이렇다.

  • #include <stdio.h>: 입출력 함수(printf, scanf 등)를 쓰려고 불러오는 것. 이게 없으면 printf를 모른다고 한다.
  • int main(void): 프로그램이 시작되는 곳. C 프로그램은 항상 main부터 실행된다.
  • { }: main이 실행할 내용을 묶는 중괄호.
  • printf(...): 화면에 출력.
  • ;: 명령 하나가 끝났다는 표시. 문장 끝마다 붙인다.
  • return 0;: 프로그램이 문제없이 끝났다고 운영체제에 알려주는 값.
SECTION 03

주석

코드에 설명을 남길 때 쓴다. 컴파일할 때는 무시된다.

C
// 한 줄 주석

/*
   여러 줄
   주석
*/

내가 짠 코드도 일주일 지나면 남의 코드처럼 보여서, 짧게라도 적어두면 나중에 편하다. 코드 한 줄을 잠깐 꺼두고 싶을 때(주석 처리)도 많이 쓴다.

SECTION 04

오류 종류

종류 언제 나오나 예
문법 오류 컴파일할 때 세미콜론 빠짐, 괄호 짝 안 맞음
논리 오류 실행은 되는데 결과가 이상함 계산식을 잘못 짬

문법 오류는 컴파일러가 줄 번호까지 알려주니까 그래도 찾기 쉽다. 진짜 힘든 건 논리 오류다. 에러는 안 나는데 답이 틀리니까 직접 값을 찍어보면서 따라가야 한다.

오류 메시지는 첫 번째 것부터 보는 게 좋다. 앞에서 하나 틀리면 뒤에 줄줄이 에러가 따라 나오기도 해서, 첫 번째만 고치면 나머지가 한 번에 사라지는 경우가 많다.
